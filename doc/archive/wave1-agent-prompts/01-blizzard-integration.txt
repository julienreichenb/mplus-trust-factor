Functional scope
----------------
Implement a typed Blizzard client for EU with region-ready host/namespace configuration.

OAuth:
- Client credentials token manager.
- POST to official token endpoint.
- Basic auth.
- Cache token until expiry minus safety window.
- Deduplicate concurrent token refreshes.
- Never log client secret or access token.

Required operations, after verifying live docs:
1. Resolve realm metadata.
2. Fetch character profile summary.
3. Fetch equipment summary.
4. Fetch specializations/talent information exposed by current Profile API.
5. Fetch character media/avatar.
6. Fetch character Mythic Keystone profile index.
7. Fetch current and selected historical season M+ profile.
8. Fetch current M+ season index/details.
9. Fetch M+ dungeon index/details.
10. Fetch item details/media only for equipped/key item IDs and cache aggressively.
11. Support future connected-realm leaderboard calls behind an explicit method, but do not bulk crawl them.

Expected endpoint templates to verify:
- `/profile/wow/character/{realmSlug}/{characterName}`
- `/equipment`
- `/specializations`
- `/media`
- `/mythic-keystone-profile`
- `/mythic-keystone-profile/season/{seasonId}`
- game-data season/dungeon/item/spec endpoints listed in API-SOURCES-AND-REQUEST-BUDGETS.txt

Normalization
-------------
Map Blizzard payloads into shared DTOs:
- CanonicalCharacter.
- CharacterSnapshotDTO.
- EquipmentSnapshotDTO.
- TalentSnapshotDTO.
- MythicRunDTO where the API exposes runs.
- Static class/spec/realm/season/dungeon records.

Rules:
- Character and realm names are display values, not keys.
- Preserve provider IDs and canonical links.
- Normalize character identity using shared helpers.
- Preserve raw source provenance and fetch timestamps.
- Support names containing accents and apostrophes.
- Do not infer account identity.

Request efficiency
------------------
- Use endpoint-specific TTLs.
- Shared request fingerprint/cache adapter.
- In-flight request deduplication.
- Configurable low concurrency.
- Retry idempotent requests only.
- Honor Retry-After and 429.
- Conditional requests if the endpoint provides ETag/Last-Modified.
- Batch item details logically but do not exceed documented API behavior.
- Fetch item details only for equipment currently needed by a character page or key-item detector.
- Avoid leaderboard scanning for population discovery.

Error handling
--------------
Map to shared errors:
- NOT_FOUND
- UNAUTHORIZED_PROVIDER
- RATE_LIMITED
- PROVIDER_UNAVAILABLE
- INVALID_PROVIDER_RESPONSE
- PRIVATE_OR_RESTRICTED
- TRANSIENT_NETWORK
- CONFIGURATION_ERROR

Include provider response request ID/headers when safe.

Acceptance criteria
-------------------
- Provider works entirely in fixture mode.
- Optional live smoke script works when credentials are present.
- No live API call in unit tests.
- All required provider methods return shared normalized DTOs.
- Token refresh is race-safe.
- Region is configurable and EU is default.
- Exact namespace/locale behavior is covered by tests.
- Item requests are cached and limited to requested IDs.
- No account-wide claim is inferred.
- Lint, strict typecheck, tests, and package build pass.
- `doc/agents/01-blizzard.md` is complete.

- Store provider secrets.
