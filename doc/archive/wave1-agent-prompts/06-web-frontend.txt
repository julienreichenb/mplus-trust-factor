AGENT 6 — VUE WEBSITE
=====================

Start in Cursor Plan mode.

Role and ownership
------------------
Build the Vue 3 MVP website against Agent 0/Agent 5 API contracts.

Primary ownership:
- `apps/web/**`
- `doc/architecture/frontend/**`
- frontend fixtures/mocks in the web app

Do not duplicate scoring logic in the browser.

Plan-mode deliverable
---------------------
Write `doc/plans/06-frontend.md` before code. Include:
- Route/page map.
- component tree.
- API state model.
- loading/stale/queued/error UX.
- radar chart design.
- comparison UX.
- admin model editor.
- accessibility and responsive plan.
- entitlement-ready rendering.
- No implementation until review/transition.

Pages
-----
1. Home/search `/`
- Region selector, EU default.
- Realm autocomplete.
- Character name input.
- Recent searches stored locally, no account required.
- Clear validation.
- Search submits canonical URL.

2. Character profile `/character/:region/:realm/:name`
Header:
- Character name, realm, region.
- class/spec/role.
- item level.
- overall Trust Factor 0–100.
- S–D grade.
- confidence.
- data freshness.
- refresh button/status.

Main:
- Radar/spider chart:
  - Performance
  - Survival
  - Utility
  - Experience
  - Mythic Raid
- Dimension cards:
  - score
  - model weight
  - confidence
  - main positive/negative contributors
- Authenticity section:
  - authenticity score
  - probabilistic red flags
  - reroll context
- Last and highest analyzed run:
  - dedupe if identical
  - key, dungeon, date, performance summary, coverage
- Equipment/talents:
  - current summary
  - key items/trinkets when returned
- Historical season summary.
- Sources and attribution, including Raider.IO link when applicable.
- Model version and calculation time.
- Clear "data incomplete/hidden" warning.

3. Comparison `/compare`
- Add 2–10 characters.
- Fetch one comparison request.
- Sort by overall or dimension.
- Overlaid radar chart with selectable candidates.
- Table:
  - grade/score
  - confidence
  - each dimension
  - authenticity
  - red flags
- Deltas:
  - global
  - per dimension
  - versus group median/best
- Clearly show incompatible season/model state instead of silently comparing.

4. Admin `/admin/models`
- Protected.
- List model versions/status.
- Clone active model into draft.
- Edit:
  - dimension weights
  - nested metric weights
  - grade thresholds
  - confidence parameters
  - boost thresholds
- Validate before save.
- Show weight sum and errors.
- Trigger fixture backtest.
- Activate immutable version with confirmation.
- Mechanic-rule page can be minimal or a documented follow-up depending on backend contract.

UI behavior
-----------
- Use typed API client generated from or aligned with OpenAPI.
- No API secrets.
- Pinia only for cross-page state; avoid unnecessary global state.
- Query cancellation on route change.
- Debounced realm autocomplete.
- Skeleton loading.
- Queued refresh polling with backoff and stop conditions.
- Stale data remains visible while refresh runs.
- Retry actions for transient failure.
- Friendly states:
  - character not found
  - logs hidden
  - insufficient data
  - provider degraded
  - Raider.IO disabled
- Do not display "boosted" as proven fact.

Radar chart
-----------
- Use ECharts radar.
- Accessible textual equivalent below chart.
- Stable dimension order.
- Tooltips show score, confidence, and weight.
- Comparison can toggle series to avoid visual overload.
- No misleading axis scaling; fixed 0–100.

Design
------
- Dark, game-compatible aesthetic without copying Blizzard/Raider.IO assets.
- Performance-focused, dense but readable.
- Responsive down to mobile.
- Keyboard navigation.
- WCAG-aware color contrast.
- Grade is not communicated by color alone.
- Avoid excessive animation.

Freemium readiness
------------------
- API returns entitlements/field visibility.
- Components handle locked details without fetching hidden data when possible.
- Launch configuration may expose everything.
- No payment flow.

Testing
-------
- Component tests:
  - score header.
  - confidence warning.
  - red flags.
  - radar fallback text.
  - stale/queued.
- Router tests.
- API mock tests.
- Comparison 2–10 validation.
- Admin weight validation.
- Playwright happy paths:
  - search -> profile
  - queued refresh -> completed profile
  - comparison
  - admin model draft/validate
- Accessibility smoke tests.
- No console errors.

Acceptance criteria
-------------------
- Search/profile/compare/admin routes work in fixture mode.
- Overall score and S–D grade are prominent.
- Radar chart has fixed 0–100 axes and accessible text.
- Missing data and confidence are visible.
- Comparison shows model/season compatibility.
- Raider.IO attribution is displayed only when its data is used.
- Admin cannot activate invalid weights.
- Responsive and keyboard usable.
- Lint, typecheck, unit tests, Playwright smoke, build pass.
- `doc/agents/06-frontend.md` is complete.

Do not
------
- Reimplement score formulas.
- Fetch provider APIs directly from the browser.
- Expose admin/provider secrets.
- Use copyrighted game art without a documented license.
