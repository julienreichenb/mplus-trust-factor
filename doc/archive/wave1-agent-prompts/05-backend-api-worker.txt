===================================================================

Start in Cursor Plan mode.

Public API v1
-------------
Implement versioned routes with schema validation and OpenAPI.

Suggested routes:

Metadata/search:
- GET `/api/v1/meta`
- GET `/api/v1/realms?region=eu&query=...`
- GET `/api/v1/characters/search?region=eu&realm=...&name=...`

Character:
- GET `/api/v1/characters/:region/:realm/:name`
- POST `/api/v1/characters/:region/:realm/:name/refresh`
- GET `/api/v1/characters/:region/:realm/:name/refresh-status`
- GET `/api/v1/characters/:region/:realm/:name/history`
- GET `/api/v1/characters/:region/:realm/:name/runs?kind=latest|highest`

Comparison:
- POST `/api/v1/comparisons`
  body: 2–10 character identities
  optional score model/profile

Scores:
- GET `/api/v1/characters/:.../scores`
- GET `/api/v1/score-models/public`

Admin:
- GET/POST `/api/v1/admin/score-models`
- POST `/api/v1/admin/score-models/:id/validate`
- POST `/api/v1/admin/score-models/:id/backtest`
- POST `/api/v1/admin/score-models/:id/activate`
- POST `/api/v1/admin/characters/:id/recalculate`
- CRUD for MechanicRule, minimally if contracts support it

Jobs:
- GET `/api/v1/jobs/:id`

Response behavior
-----------------
Character GET:
- 200 fresh.
- 200 stale with `freshness=STALE` and refresh queued.
- 202 when no score exists and ingestion is running.
- 404 only when identity is confirmed absent or invalid.
- Include:
  - score snapshot
  - dimensions
  - confidence
  - red flags
  - freshness
  - source attribution
  - model version
  - last/highest run summaries
  - equipment/talents summary
  - eligibility/addon status

Refresh:
- Deduplicate by character + requested model/season.
- Enforce manual cooldown.
- Return existing job if one is active.
- Apply API rate limiting per client/IP.

Worker queues/processors
------------------------
Implement typed processors:
- resolve-character
- refresh-blizzard
- refresh-raiderio
- refresh-warcraftlogs-summary
- match-detailed-runs
- analyze-wcl-run
- extract-metrics
- calculate-score
- refresh-character-finalize
- generate-addon-export
- prune-raw-artifacts

Or a smaller equivalent DAG with clear stages.

Requirements:
- Job dedupe keys.
- Idempotent DB writes.
- Retry classification:
  - transient provider error: retry/backoff
  - not found: negative cache, no rapid retry
  - rate limited: delay using Retry-After
  - invalid payload: dead-letter/manual review
- Per-provider concurrency.
- Overall refresh status aggregation.
- Graceful shutdown.
- Failed job visibility.
- Correlation IDs across API -> job -> provider request.

Persistence
-----------
Implement repositories for:
- characters/snapshots.
- runs/participants/source refs.
- metric observations.
- score models/snapshots.
- red flags.
- external request/payload metadata.
- jobs.
- addon export metadata.

Do not put Prisma calls throughout route handlers.
Use transactions for canonical run/source/participant upserts and score snapshot writes.

Stale/caching policy
--------------------
- API response cache for stable profile DTO.
- Invalidate after score calculation.
- Character freshness is source-aware.
- Do not wait synchronously for detailed WCL work on a normal page request.
- Initial page may return partial/queued state.
- Expose source freshness separately.

Admin and monetization readiness
--------------------------------
MVP admin can use a strong environment-provided API key or minimal admin session, but:
- document it as MVP-only.
- compare constant-time.
- never expose it to public frontend bundles.
- public entitlements are represented server-side.
- API serializers can omit premium fields based on entitlement.
- all details may be public initially through configuration.

OpenAPI/errors
--------------
- Every route has request/response schema.
- Standard error envelope:
  - code
  - message
  - requestId
  - retryable
  - details only when safe
- Generate OpenAPI artifact.
- Add examples for fresh, stale, queued, no logs, and insufficient data.

Acceptance criteria
-------------------
- Fixture-mode end-to-end refresh can flow through queues to a persisted score.
- Page request returns fresh/stale/queued states correctly.
- Job dedupe prevents duplicate expensive provider work.
- Comparison rejects mixed model versions unless explicitly normalized/recomputed.
- Admin can create/validate/activate a model through protected API.
- OpenAPI is complete and buildable.
- Provider failures degrade gracefully.
- No route performs uncontrolled external calls.
- Lint, typecheck, tests, build pass.
- `doc/agents/05-backend.md` is complete.
