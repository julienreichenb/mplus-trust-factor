AGENT 2 — WARCRAFT LOGS GRAPHQL PROVIDER AND RUN ANALYSIS INPUTS
===============================================================

Start in Cursor Plan mode.

Role and ownership
------------------
Implement the Warcraft Logs public API provider and normalized detailed-run facts.

Primary ownership:
- `packages/providers/warcraftlogs/**`
- `doc/api/warcraftlogs/**`
- WCL fixtures under `tools/fixtures/warcraftlogs/**`

Do not implement final scoring. Do not edit shared contracts silently.

Plan-mode deliverable
---------------------
Write `doc/plans/02-warcraftlogs.md` before implementation.

The plan must include a live-schema spike answering:
1. How to resolve a character and canonical ID.
2. Which current GraphQL fields expose M+ rankings and key-level brackets.
3. How to discover recent public M+ reports for a character.
4. Whether ranking records contain report code/fight ID/run identifiers.
5. How to identify the latest run and highest run.
6. How to match WCL fights to Blizzard/Raider.IO runs.
7. Exact event/table queries and their point costs.
8. Pagination behavior.
9. How hidden/private/no-log cases appear.
10. A point-budget estimate for one character refresh.

If the API cannot answer an item, document the gap and a safe fallback. Do not fabricate support.

Authentication
--------------
- Implement client_credentials public API.
- Cache tokens with expiry safety margin.
- Deduplicate token refresh.
- Secret remains server-side.
- Architect optional authorization-code/PKCE extension, but do not implement private-log access in MVP.

GraphQL client
--------------
Implement:
- Typed operation documents.
- Variable validation.
- GraphQL error mapping.
- HTTP error mapping.
- operation name logging.
- request fingerprinting from operation + canonical variables.
- response schema validation where practical.
- configurable timeout.
- rate-limit cost monitoring.

Required operations
-------------------
After validating the current schema:
1. Query `rateLimitData`.
2. Resolve character by name/server/region.
3. Fetch canonical character metadata.
4. Fetch relevant M+ ranking/parse summaries:
   - current season
   - equivalent specialization
   - dungeon/encounter
   - key-level bracket where supported
   - current/recent comparison where useful
5. Discover recent public reports/runs.
6. Fetch a report by code:
   - revision
   - start/end
   - fights
   - masterData with `translate: false`
   - playerDetails if needed
   - rankings for selected fight
7. Fetch paginated, filtered events/tables for selected fight and actor:
   - Casts
   - Interrupts
   - Deaths
   - DamageTaken
   - Buffs
   - Debuffs
   - Dispels
   - Healing only for external support
   - CombatantInfo when required
8. Resolve actor/source IDs and ability IDs.

Detailed-run selection
----------------------
Provide normalized discovery candidates that allow the worker to select:
- Latest public M+ run.
- Highest key-level or highest-ranked public M+ run.
- Deduplicate when same report/fight.

Run matching:
- Expose exact identifiers and timestamps.
- Implement a match-candidate function that compares:
  - dungeon
  - key level
  - completion/start time tolerance
  - duration tolerance
  - roster overlap
- Return match confidence and evidence.
- Never merge low-confidence matches automatically.

Normalized output
-----------------
Return facts, not scores:
- WclCharacterSummary.
- WclRankingObservation.
- WclRunCandidate.
- WclReportSummary.
- WclFightSummary.
- WclActorMap.
- RunCombatFacts containing:
  - casts by ability/timestamp
  - successful interrupts and interrupted spell IDs
  - deaths
  - damage taken events/aggregates
  - aura applications/removals needed for defensives
  - dispels/purges where distinguishable
  - healing/external support events
  - combatant gear/spec/loadout if available
  - coverage/limitations
  - report code, fight ID, revision, source IDs

Do not mark damage as avoidable. Agent 4 applies MechanicRule catalog.

Rate and cost controls
----------------------
- Query and persist rateLimitData snapshots.
- Soft thresholds from environment.
- Defer expensive jobs when above threshold.
- Combine fields/aliases when it reduces point cost.
- Use `translate: false`.
- Restrict by fight IDs, source IDs, target IDs, event types, and time windows.
- Fetch masterData once per report revision.
- Follow `nextPageTimestamp`; guard against loops.
- Cache report/fight/revision forever unless revision changes.
- Store large raw event pages compressed via RawArtifact abstraction.
- Store compact normalized facts in PostgreSQL.
- Do not fetch all recent reports in full.
- Analyze only latest and highest selected run.

Metric-support research

- DPS/performance percentile.

- interrupts.

- defensives.

Acceptance criteria
-------------------
- Public OAuth and GraphQL client work in fixture mode.
- Optional live smoke script can resolve one configured character and query rateLimitData.
- Latest/highest discovery has documented evidence and fallback.
- Detailed analysis fetch plan is minimal and paginated safely.
- Immutable revision caching works.
- Provider returns normalized combat facts without final scoring.
- Hidden/no-log state is distinguishable from API failure.
- No private API is accessed without explicit future authorization.
- Lint, typecheck, tests, and build pass.
- `doc/agents/02-warcraftlogs.md` is complete.

Do not
------
- Scrape WCL pages.
- Fetch all events for all runs.
- Hardcode English spell names as identifiers.
- Claim CC usefulness without mechanic context.
- Compute boost or final Trust Factor.
