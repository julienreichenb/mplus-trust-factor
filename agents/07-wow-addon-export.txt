AGENT 7 — WORLD OF WARCRAFT ADDON AND STATIC DATA EXPORTER
=========================================================

Start in Cursor Plan mode.

Role and ownership
------------------
Build:
1. A safe Retail WoW addon proof of concept.
2. A Node/TypeScript exporter that turns eligible score snapshots into Lua data shards.

Primary ownership:
- `addon/**`
- `tools/addon-exporter/**`
- `doc/architecture/addon/**`

Plan-mode deliverable
---------------------
Write `doc/plans/07-addon.md` before code. Include:
- Current Retail addon interface/API research.
- Safe LFG hook strategy.
- Taint/protected-frame risks.
- Tooltip fallback.
- dataset format and partitioning.
- exporter memory/size estimates.
- packaging/update plan.
- No implementation until review/transition.

Critical technical constraints
------------------------------
- WoW Lua addons cannot perform arbitrary HTTP requests.
- The addon consumes static data generated outside the game.
- Avoid protected actions and taint.
- Use safe hooks such as `hooksecurefunc` or supported callback/event APIs after validating the current Retail UI.
- Do not replace Blizzard Group Finder behavior.
- If directly placing a grade in an applicant row is unsafe or unstable, implement tooltip integration first and
  document the row-label feature as experimental.

Addon UX
--------
MVP:
- Show overall grade S/A/B/C/D for a character:
  - in applicant row when safe
  - in tooltip on hover
- Tooltip:
  - numeric Trust Factor
  - grade
  - confidence bucket
  - last update date
  - limited red flags:
    - boost suspected
    - atypical progression
    - logs hidden
    - insufficient data
    - probable/confirmed reroll
- Optional command to copy/open profile URL through normal user copy flow.
- Settings:
  - enable/disable row grade
  - enable/disable tooltip
  - show numeric score
  - minimum confidence
  - debug mode
- Slash command:
  - `/mpt status`
  - `/mpt lookup Name-Realm`
  - `/mpt debug`

No detailed dimensions in the initial in-game list.

Static dataset
--------------
Input:
- active AddonExport or database/query DTO from backend.
- only eligible region/season/model records.

Output:
- deterministic Lua shards.
- metadata file:
  - format version
  - generated timestamp
  - region
  - season
  - score model version
  - character count
  - checksum
- character value:
  - integer score
  - grade enum/compact code
  - confidence bucket
  - public red-flag bitset
  - freshness bucket/date
  - optional profile key

Canonical lookup key:
- region + normalized realm slug + normalized character name.
- Follow shared normalization semantics.
- Preserve a test vector shared between TypeScript exporter and Lua lookup.

Partitioning
------------
Research and benchmark:
- by region/realm prefix.
- by realm and first character hash.
- deterministic shard names.
- lazy loading where WoW addon packaging supports it.
- compact Lua tables.
- avoid huge nested structures and duplicate strings.

Do not prematurely invent binary compression that Lua cannot cheaply decode.
Measure:
- generated archive size.
- Lua memory after load.
- lookup time.
- 10k/100k/target EU datasets using synthetic records.

Eligibility
-----------
Exporter selects:
- current EU season.
- active score model.
- >=20 runs.
- and baseline dungeon completion OR top-25% cutoff.
- valid non-stale score.
- policy should be configurable.
- Website-searched ineligible characters remain excluded unless explicitly configured.

LFG integration research
------------------------
Inspect current Retail Blizzard UI/addon APIs and document:
- Applicant list data functions/events.
- Available character name/realm in applicant/member rows.
- Secure/protected frame boundaries.
- Existing addon-compatible hook points.
- Impact of combat lockdown.
- Localization.
- Group applicant updates.
- Compatibility with common UI addons where possible.

Implement:
- an adapter layer so UI hook code is isolated.
- safe no-op fallback.
- tooltip lookup even if row injection fails.
- no frame polling loop when event callbacks exist.

Packaging
---------
Create:
- `.toc` with interface version resolved at build/release time.
- addon source layout.
- license placeholder chosen by project owner, do not assume.
- local packaging script.
- release ZIP generation.
- optional future GitHub Actions integration contract for Agent 8.
- document CurseForge/Wago packaging options; do not publish without credentials/approval.

Tests
-----
Exporter:
- deterministic output.
- identity normalization.
- shard routing.
- eligibility filter.
- red-flag bitset.
- checksum.
- Lua escaping.
- large synthetic dataset benchmark.
- no private/premium detail leakage.

Addon:
- Lua syntax check.
- lookup test vectors.
- missing realm/name.
- stale dataset.
- settings migration.
- tooltip rendering.
- simulated applicant update adapter.
- no error when Blizzard UI module is not loaded.
- no protected action.

Acceptance criteria
-------------------
- Exporter generates deterministic Lua dataset from fixture scores.
- Addon loads without Lua errors in a test environment/manual checklist.
- Lookup returns correct grade/score for test vectors.
- Tooltip works independently of applicant-row injection.
- Row grade is implemented only through a documented safe hook.
- Dataset contains no detailed dimensions or sensitive/admin data.
- Synthetic size/memory benchmark is documented.
- Addon metadata exposes freshness/model version.
- Lint, typecheck, tests, build/package pass.
- `doc/agents/07-addon.md` is complete.

Do not
------
- Add network code to Lua.
- Hook protected actions insecurely.
- Copy Raider.IO addon code or assets.
- Publish to CurseForge/Wago.
- Fetch external APIs from exporter; it reads internal snapshots only.
