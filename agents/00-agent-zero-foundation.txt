AGENT 0 — FOUNDATION, CONTRACTS, AND REPOSITORY BOOTSTRAP
========================================================

Start in Cursor Plan mode.

Your role
---------
You are the foundation architect for a brand-new M+ Trust Factor repository. You run before every
other agent. Your output must make parallel development safe and predictable.

Read all bootstrap documents supplied with this prompt:

Plan-mode requirements
----------------------
Before modifying code:
1. Inspect the empty/current repository.
2. Produce `doc/plans/00-foundation.md`.
3. Include:
   - Exact repository tree.
   - Selected stable package versions and why.
   - Shared contracts.
   - Initial Prisma models and migration plan.
   - Local developer workflow.
   - Testing strategy.
   - Parallel file ownership.
   - Risks and assumptions.
4. Do not implement until the plan has been reviewed or you are explicitly transitioned to execution.

Technical objective
-------------------
Create a production-oriented but small-VPS-friendly TypeScript monorepo with:
- pnpm workspaces.
- Node.js active LTS pinned through `packageManager`, `.nvmrc` or equivalent, and Docker image.
- Vue 3 + Vite web app.
- Fastify API.
- BullMQ worker.
- PostgreSQL + Prisma.
- Redis.
- Shared domain/contracts/config/observability packages.
- Provider package skeletons.
- Scoring package skeleton.
- WoW addon/exporter skeleton.
- Strict TypeScript, linting, formatting, tests, and build commands.
- Docker Compose for local PostgreSQL and Redis.
- Documentation folder structure.

Contract rules:
- No provider-specific response objects leak into public API DTOs.
- Use ISO timestamps at boundaries.
- Use explicit nullable/optional semantics.
- Preserve region in all identity keys.
- All score DTOs include model key/version and calculatedAt.

Database
--------
Implement the initial Prisma schema based on ARCHITECTURE-AND-DB.txt.

Required for initial migration:
- Region, Realm, Season, Dungeon, SeasonDungeon.
- GameClass, GameSpecialization.
- Character, CharacterAlias, CharacterSnapshot, EquipmentSnapshot, TalentSnapshot.
- ExternalRequest, ExternalPayload, RawArtifact.
- MythicRun, RunSourceReference, RunParticipant, RunAnalysis.
- MetricDefinition, MetricObservation, MechanicRule.
- ScoreModel, ScoreSnapshot, DimensionScore.
- RedFlagDefinition, CharacterRedFlag, ScoreDispute.
- IngestionJob, User, Entitlement, AddonExport.

You may simplify low-value fields, but not remove the core concepts without an ADR.
Create:
- Initial migration.

- Seed script:
  - EU region.
  - Placeholder/current season seed configurable and clearly marked.
  - Default score model v1 from COMMON-CONTEXT.
  - Grade thresholds.
  - Metric definition keys.
  - Red flag definitions.

Acceptance criteria
-------------------
- Fresh clone can install with one documented command.
- `docker compose` starts PostgreSQL and Redis locally.
- Initial migration applies to an empty DB.
- Seed is idempotent.
- API health/readiness tests pass.
- Web, API, worker, and packages build.
- Lint, strict typecheck, and unit tests pass.
- No external credentials are required in fixture mode.
- OpenAPI document is generated.
- Other agents can work only inside their declared ownership paths.
- No secret or `.env` file is committed.
- `doc/agents/00-foundation.md` follows AGENT-OUTPUT-TEMPLATE.txt.

Do not
------
- Implement real external API integrations.
- Implement the final scoring model.
- Build CI/CD beyond a minimal local Docker foundation; Agent 8 owns production delivery.
- Add speculative microservices.
- Hide unresolved decisions.
